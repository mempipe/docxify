# Contributing

Thank you for your interest in contributing to [docxify](https://github.com/mempipe/docxify). We welcome contributions to the code and the documentation.

## Open an issue first

Before you open a pull request, please [create an issue](https://github.com/mempipe/docxify/issues/new) to discuss the change. This lets us check that the change fits the project's direction and that nobody is already working on it.

If you are not sure whether a change is needed, create an issue anyway. We can discuss it there.

## Making changes

1. Fork and clone the repository.
2. Create a separate branch for your change.
3. Make your change, and add or update tests that cover it.
4. Write commit messages as [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/).
5. Push your branch and open a pull request.

## Sign the contributor license agreement

Before we merge your pull request, you need to sign our [Contributor License Agreement](CLA.md). You sign once, and it covers your later contributions too.

To sign, post this comment on your pull request:

> I have read the CLA Document and I hereby sign the CLA

Everyone who authored a commit in the pull request must sign, each with their own comment.

We ask for this because docxify is offered under two kinds of license:

- the [Mempipe Source License](LICENSE.md), which makes the source available but is not an open source license;
- commercial licenses from Mempipe, which production use requires once a trial ends.

The agreement gives Mempipe the rights it needs to distribute your contribution under both. You keep ownership of your contribution and can use it for any other purpose.

If you contribute as part of your job, check that your employer allows it. Section 4 of the agreement explains what you are confirming.
